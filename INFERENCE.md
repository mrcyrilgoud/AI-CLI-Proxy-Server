# Companion inference API

Start with `node server.js`. The server binds to `127.0.0.1:3333` (or `PORT`). HTTP and WebSocket clients must use loopback hostnames; browser requests must have an HTTP(S) loopback Origin. Local non-browser requests without Origin remain supported.

`GET /api/tools` retains `defaultTool` and `tools: string[]` and adds `streamMode: "delta"` and `toolDetails`. Each detail contains `id`, `available`, `capabilities: {image, streaming, model}`, `streamMode`, `authenticationInstructions`, and `authenticationStatus`. Availability means an executable was found on PATH, not that inference or authentication has been tested. Status is `authenticated` when a proxy-owned key is present, otherwise `unknown`; `unknown` intentionally makes no claim about vendor-managed login. Discovery never exposes paths, raw command output, identities, or credentials.

`POST /api/inference` and `POST /api/inference-stream` accept `{tool, prompt, model?}`. `/api/low-level` and `/api/low-level-stream` are compatibility aliases. IDs are `codex`, `gemini`, `opencode`, `cursor`, `claude`, and `kiro`. Cursor resolves `cursor-agent` or `agent`, not the desktop launcher. File/image inputs are rejected; these are isolated text adapters. Model names are forwarded as one argument to the selected CLI without changing a saved vendor default.

Nonstreaming success returns `{response, streamMode: "delta"}`. SSE text events return `{response: delta, delta, streamMode: "delta"}`; append either text field once. A successful stream ends with `{done: true, streamMode: "delta"}`. Errors return sanitized `{error, code}` (plus streamMode for SSE). Never infer cumulative mode from text prefixes. Codex emits completed message records, so its deltas can arrive as complete message segments.

Requests run in a unique temporary working directory with restricted vendor arguments/configuration, no shell interpolation, and no sandbox/approval bypass. Only basic OS environment variables and the selected proxy-owned API key are passed. Vendor-managed login remains in the user's home; subscription token files are neither read nor imported by this proxy. The timeout is 120 seconds; stdout plus stderr are limited to 5 MiB. Disconnects terminate the process group, with SIGKILL escalation after one second. Working directories are removed after subprocess close. Stderr is never returned or logged because it may contain credentials or private context.

`PUT /api/tools/:id/credential` accepts only `{apiKey}`. `DELETE /api/tools/:id/credential` removes the proxy-owned key. Supported key environments are CODEX_API_KEY, GEMINI_API_KEY, CURSOR_API_KEY, ANTHROPIC_API_KEY, and KIRO_API_KEY. OpenCode uses provider-specific vendor login and has no generic key endpoint. Credentials use native `@napi-rs/keyring` entries under service `AI-CLI-Proxy-Server.api-keys.v1`, keyed by tool ID, and are never returned. OAuth/session-token fields and known Anthropic subscription tokens are rejected. Use the official CLI for subscription login; there is no session-token collection flow.

The coding harness keeps its original four tool IDs and arguments. It is not an isolated inference API.

Run `npm test -- --runInBand` for fixture executables and harness regression tests. Run `PROXY_NATIVE_KEYCHAIN_TEST=1 npm test -- --runInBand credentials.test.js` for a disposable native Keychain round trip. Live vendor inference is separate from fixture coverage and is not performed by these tests.
